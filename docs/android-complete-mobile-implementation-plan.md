**التاريخ:** 2026-11-24  
**نوع الوثيقة:** خطة تدقيق وتنفيذ واختبار، وليست إعلان اكتمال المنتج.

## 1. الملخص التنفيذي

CADCraft ليس محرك رسم بسيطاً؛ إنه تطبيق CAD واسع الوظائف مكتوب بـ Rust، ويضم محرك مستندات وأوامر ورسوماً وطبقات وأدوات تحرير وواجهات UI وملفات واستيراداً وتصديراً. توجد حزمة Android منفصلة تستخدم eframe/GameActivity وتعيد استخدام `CadApp` و`Session` ومحرك CAD الأصلي.

القرار المعماري:
- الاحتفاظ بمحرك CADCraft وبيانات المستندات والأوامر والهندسة وعمليات الرسم والتصيير وصيغ الملفات الأصلية.
- تطوير مضيف Android وخدمات المنصة وتجربة اللمس والواجهات المحمولة.
- عدم تحويل التطبيق إلى WebView، وعدم إنشاء محرك CAD ثانٍ أو تفريع منطق الأوامر.
- إبقاء تطبيقات سطح المكتب والويب سليمة، وعزل تغييرات Android قدر الإمكان.

**الحالة التي تثبتها الشيفرة عند مرجع الدراسة:**
1. حزمة Android منفصلة ومهيأة لـ ARM64 مع مدخل GameActivity.
2. المضيف يستدعي `CadApp::new(Session::new(), Services::default())`، ولا يثبت وجود خدمة Android لاختيار المستندات.
3. شيفرة الواجهة المشتركة تضم سطر أوامر متقدماً وسجلّاً وإكمالاً تلقائياً وIME وكلمات تفاعلية.
4. مسارات OPEN وSAVE AS وEXPORT وIMPORT وPUBLISH في الواجهة تستخدم حدود اختيار الملفات؛ وجود الأوامر والـ codecs لا يساوي وجود وصول Android إلى الملفات.
5. واجهة CAD الأساسية ما زالت ذات تنظيم مكتبي: قوائم ولوحات وDock وشريط حالة وسطر أوامر عائم.
6. كتالوج العربية موجود في `crates/ui-egui/src/i18n/ar.tsv`، لكن وجوده لا يثبت اكتمال الترجمة أو صحة RTL.
7. نجاح بناء CI والتحقق من APK هو تحقق تغليف، وليس اختبار تشغيل أو وظائف على هاتف فعلي.
8. دعم DWG على سطح المكتب لا يثبت دعم DWG في Android؛ يبقى غير معلن حتى اختبار الجسر والقراءة والكتابة على الجهاز.

هذه دراسة ثابتة للمصدر وبنية المشروع ونقاط الربط الرئيسية، وليست ادعاءً بأن كل دالة في كل ملف قد خضعت لاختبار سلوكي. البنود التي تحتاج تشغيل الجهاز أو استكمال تتبع مساراتها موضحة أدناه كمهام تدقيق واختبار.

## 2. أهداف المنتج ومعايير النجاح

### الهدف
تطبيق CAD عربي أصلي على Android، يعمل على الهاتف والتابلت، ويوفر مساحة رسم عملية وأدوات CAD موثوقة مع ملفات قابلة للفتح والحفظ والتبادل.

### مبادئ تجربة الاستخدام
- الرسم هو العنصر المركزي، وليس القوائم أو اللوحات.
- الأوامر والأدوات الأساسية تصل إليها اليد بسهولة.
- لا تتداخل إيماءات الرسم مع التحريك والتكبير أو التحكم بالواجهة.
- كل زر ظاهر يؤدي وظيفة مكتملة، أو يكون معطلاً مع سبب مفهوم.
- لا تضيع التعديلات عند فشل الحفظ أو تبديل التطبيق.
- الواجهة العربية RTL، مع إبقاء الإحداثيات والأوامر والمسارات والرموز التقنية باتجاه مناسب.
- هاتف وتابلت بتخطيطين متكيفين، لا مجرد تصغير تخطيط سطح المكتب.
- لا يتم حذف أو إضعاف خصائص المحرك الأصلية لمجرد تسهيل واجهة الهاتف.

### بوابات النجاح النهائية
1. تثبيت التطبيق وتشغيله واستئناف الجلسة على أجهزة Android المستهدفة.
2. رسم وتعديل وتحديد وحفظ وإعادة فتح رسم DXF دون فقد هندسي.
3. تنفيذ مسارات التصدير المدعومة إلى PDF وSVG وPNG من الهاتف.
4. عمل سطر الأوامر والاقتراحات والسجل ولوحة مفاتيح Android.
5. عدم وجود عناصر رئيسية مقصوصة أو مخفية أو غير قابلة للوصول.
6. اجتياز اختبارات اللمس واللمس المتعدد والقلم ولوحة المفاتيح.
7. اكتمال تدقيق الترجمة وRTL وعدم انقلاب الأرقام والإحداثيات.
8. اجتياز اختبارات الأداء والاستقرار والذاكرة على هاتف وتابلت حقيقيين.
9. عدم إعلان دعم أي تنسيق أو أداة قبل اجتياز اختبارها.

## 3. صورة البنية الحالية والملفات المحورية

| الطبقة | المسارات المحورية | الدور |
|---|---|---|
| مضيف Android | `apps/cadcraft-android/src/lib.rs` | GameActivity، إنشاء CadApp، إعداد codecs، lifecycle |
| Android Manifest/Java | `apps/cadcraft-android/app/src/main/` | حزمة Android ومدخل النشاط |
| واجهة CAD | `crates/ui-egui/src/lib.rs` | CadApp، الحالة، توزيع الواجهات، خدمات المضيف |
| مساحة الرسم | `crates/ui-egui/src/canvas.rs` و`canvas/*` | الإدخال والرسم والتحديد والمقابض والتنقل |
| سطر الأوامر | `crates/ui-egui/src/cmdline.rs` | prompt، history، autocomplete، IME |
| القوائم | `crates/ui-egui/src/menus.rs` | شجرة القوائم وربط أوامر الواجهة |
| اللوحات | `crates/ui-egui/src/docking.rs` و`palettes.rs` و`layers.rs` | Tool Sets وLayers وProperties وبقية اللوحات |
| فتح الملفات | `crates/ui-egui/src/opening.rs` | القراءة الخلفية من مسار ملف |
| الاستيراد والتصدير | `crates/ui-egui/src/exchange.rs` | EXPORT/IMPORT/PUBLISH/PREVIEW |
| أوامر الملفات | `crates/engine/src/cmd/file.rs` | أوامر OPEN/SAVE/SAVEAS وواجهات IO hooks |
| العربية | `crates/ui-egui/src/i18n.rs` و`i18n/ar.tsv` | ترجمة النصوص |
| التنسيق | `crates/io` وما يتصل به | DXF وSVG وPNG وPDF وغيرها بحسب الميزات الفعلية |
| البناء | `.github/workflows/android-build.yml` وملفات Gradle/Cargo | إنتاج APK والتحقق من محتوياته |

**تنبيه:** هذه قائمة نقاط الدخول التي يجب تدقيقها، وليست قائمة حصرية بكل الوحدات أو كل أوامر المحرك.

## 4. التصميم المستهدف

### 4.1 الهاتف — عمودي
- شريط علوي صغير: اسم الرسم، حالة الحفظ، تراجع، إعادة، اختيار، قائمة المزيد.
- مساحة رسم تملأ معظم الشاشة.
- شريط أدوات سفلي قابل للتبديل بين مجموعات: رسم، تعديل، قياس/أبعاد، تعليق/نص.
- سطر أوامر مطوي افتراضياً إلى صف واحد واضح، ويمكن توسيعه إلى سجل واقتراحات.
- درج سفلي أو جانبي للطبقات والخصائص والكتل والمراجع، يظهر عند الطلب ويغلق بإيماءة واضحة.
- شريط حالة مختصر للإحداثيات والالتقاط وOrtho/Grid/Snap.
- عدم إبقاء أعمدة Dock المكتبية مفتوحة افتراضياً.

### 4.2 الهاتف — أفقي
- المحافظة على مساحة الرسم مع شريط أدوات جانبي أو سفلي حسب المساحة.
- عدم وضع لوحة ثابتة فوق مساحة الرسم.
- سطر أوامر قابل للتصغير مع مراعاة ارتفاع لوحة المفاتيح.
- السماح بتبديل موضع الأدوات لتفادي تداخلها مع اليد أو منطقة الرسم.

### 4.3 التابلت
- مساحة عمل CAD موسعة.
- Tool Sets على جانب، وLayers/Properties على الجانب المقابل عند توفر العرض.
- سطر أوامر قابل لتغيير الارتفاع.
- لوحات قابلة للطي وإعادة الترتيب دون نوافذ نظام مكتبية عائمة.
- دعم لوحة مفاتيح فعلية واختصارات وقلم مع بقاء أزرار اللمس.

### 4.4 نظام التصميم
- أحجام لمس مستهدفة لا تقل عن 48dp للأوامر المتكررة، مع تباعد يمنع النقر الخاطئ.
- تسلسل بصري ثابت: الرسم، الأداة النشطة، الخصائص، الأوامر.
- ألوان تباين جيدة في الوضعين الفاتح والداكن.
- أيقونات موحدة مع تسميات أو تلميحات، وعدم الاعتماد على رموز مبهمة وحدها.
- دعم الحواف الآمنة وInsets ولوحة المفاتيح.
- تخطيط يعتمد على العرض المتاح والاتجاه، لا على نوع الجهاز فقط.

## 5. مسارات العمل التفصيلية

## P0 — خدمات Android والملفات والحفظ والتصدير

### المشكلة
مضيف Android يستخدم `Services::default()`. واجهة الملفات تطلب خدمات اختيار ملفات من المضيف. كما أن بعض المسارات الداخلية مبنية على `Path` وعمليات قراءة من نظام الملفات؛ URI الخاص بـ SAF ليس مسار ملف عادي.

### المطلوب
1. جرد كل استعمالات `Pick` و`pick_then` وعمليات `read_file` و`write_file` و`deliver` ومسارات الاستيراد والنشر والسكريبتات والمراجع الخارجية والصور والخطوط.
2. تصميم حد خدمة محايد للمنصة يدعم اختيار مصدر/وجهة وقراءة/كتابة bytes أو stream، مع نتائج غير متزامنة.
3. تنفيذ Android SAF عبر `ACTION_OPEN_DOCUMENT` و`ACTION_CREATE_DOCUMENT` وActivity Result APIs.
4. تمرير URI ومعلومات الاسم وMIME وفتح stream عبر ContentResolver؛ عدم تحويل URI إلى مسار وهمي.
5. تعريف ملكية صلاحيات URI الدائمة عند الحاجة، ومعالجة مزودي الملفات السحابية.
6. القراءة إلى worker thread مع حد حجم وقياس تقدم وإلغاء، مع احترام حدود الذاكرة.
7. الكتابة إلى ملف مؤقت أو stream آمن قدر الإمكان، وإغلاقه والتحقق من نجاحه قبل تحديث حالة المستند.
8. عند فشل الحفظ تبقى حالة الرسم dirty ويظهر الخطأ بوضوح؛ لا يتم إظهار نجاح زائف.
9. تمييز Save عن Export: الأول يحفظ المستند القابل للتحرير، والثاني ينتج نسخة مشتقة.
10. إضافة واجهة حفظ باسم، واختيار تنسيق وإصدار DXF وخيارات الكتابة المتاحة.
11. إضافة شاشة تصدير للهاتف تشمل PDF/SVG/PNG، الإعدادات التي يدعمها المحرك، اسم الملف، المعاينة، والوجهة.
12. مراجعة استيراد DXF/صور/ملفات أخرى، وSCRIPT وXREF وInsert file؛ ما لا يمكن تشغيله عبر URI يعاد تصميمه أو يعطل بوضوح.
13. إنشاء قائمة Recent آمنة؛ لا تعتمد على مسارات مؤقتة غير صالحة بعد إعادة تشغيل التطبيق.
14. استعادة المستندات غير المحفوظة عند إغلاق قسري أو نفاد ذاكرة.

### الاختبارات
- فتح DXF من Downloads.
- فتح من مزود ملفات سحابي عند توفره.
- حفظ فوق ملف موجود بموافقة المستخدم.
- Save As إلى اسم وموقع جديدين.
- قتل التطبيق أثناء الحفظ والتحقق من عدم تلف آخر نسخة.
- إعادة فتح الملف المحفوظ ومقارنة الكيانات والطبقات والوحدات والإعدادات.
- تصدير PDF/SVG/PNG وفتح الناتج في عارض خارجي.
- إلغاء منتقي الملفات وعدم تغيير الرسم.
- اختبار الملفات الكبيرة وحدود الذاكرة.

### معيار القبول
تكتمل دورة Open → Edit → Save → Close → Reopen دون فقد، وتكتمل صادرات التنسيقات المعلنة على جهاز حقيقي.

## P1 — سطر الأوامر وتجربة إدخال النص

### ما هو موجود
`cmdline.rs` يتضمن buffer وhistory وrecent input وexpanded state وIME composition وTab completion وDynamic Input وprompt keywords. المطلوب إعادة تقديمه على الهاتف لا استبداله.

### المطلوب
1. وضع collapsed console بعرض الشاشة في أسفل مساحة العمل.
2. صف مطوي يعرض prompt والأمر النشط وحقل الإدخال وزر توسيع.
3. وضع موسع يعرض سجل الأوامر قابلاً للتمرير، حقل الإدخال، الاقتراحات والكلمات التفاعلية.
4. زر واضح لإظهار/إخفاء لوحة المفاتيح، مع عدم فقدان حالة الأمر عند إغلاقها.
5. تفعيل Android IME بصورة صحيحة: composition/preedit، cursor، selection، paste، backspace، Enter.
6. دعم Escape للإلغاء، Tab للإكمال، الأسهم للتنقل بالسجل/الاقتراحات، مع بدائل لمس.
7. عدم استهلاك Enter مرتين بين IME والمحرك.
8. دعم العربية والإنجليزية والأرقام والإشارات والفواصل والنقطة العشرية والإحداثيات.
9. إبقاء أسماء الأوامر والـ aliases كما هي، مع عرض وصف عربي.
10. الضغط على keyword chips ينفذ نفس الاختيار الذي يقبله المحرك.
11. توفير زر إعادة آخر أمر، ومسح السجل، ونسخ نتيجة الأمر.
12. لا يسمح للسجل بأن يغطي الرسم بالكامل؛ يراعى ارتفاع الشاشة ولوحة المفاتيح.
13. اختبار الأوامر التفاعلية متعددة الخطوات، لا مجرد تنفيذ أمر ذي معاملات جاهزة.

### معيار القبول
تنفيذ LINE بإحداثيات أو مسافة/زاوية، ثم إكماله أو إلغاؤه، واستخدام الاقتراحات والسجل وتكرار الأمر، باللمس ولوحة Android، دون فقد التركيز أو تشوه النص.

## P2 — نموذج التفاعل باللمس والرسم

### المطلوب
1. كتابة جدول حالات موحد لكل إيماءة: Idle، Draw، Select، Drag/Grip، Pan، Pinch، UI interaction، Command prompt.
2. اعتماد قاعدة واضحة: إصبع واحد ينفذ الأداة النشطة؛ إصبعان للتحريك/التكبير؛ عناصر الواجهة لا تمرر أحداثها إلى مساحة الرسم.
3. عند انتقال إصبع واحد إلى إصبعين، إلغاء عملية الرسم المؤقتة بطريقة لا تترك كياناً ناقصاً.
4. عند رفع الإصبع في عملية الرسم، تثبيت الكيان مرة واحدة، مع إظهار نتيجة ثابتة.
5. عدم إنشاء نقاط مكررة من أحداث Touch وPointer لنفس الإيماءة.
6. تحديد Touch ID الأساسي وتجاهل الأصابع الثانوية بطريقة ثابتة.
7. دعم التحديد بالنقر والنافذة والتقاط الكائنات، مع مساحة حساسة أكبر من المؤشر المرئي.
8. إظهار grips بحجم لمس مناسب وعدم التضحية بالدقة الهندسية.
9. تحسين Object Snap وTracking وOrtho وPolar وGrid على اللمس.
10. وضع Pan/Select منفصل قابل للتبديل إذا تعذر إزالة الالتباس في بعض الأدوات.
11. دعم قلم stylus: hover/pressure/buttons عند توفر API، دون جعل القلم شرطاً للرسم.
12. منع إيماءة الرجوع في Android من تدمير عملية رسم غير محفوظة.
13. حفظ دقة الإحداثيات الهندسية وعدم ربطها بكثافة الشاشة.
14. اختبار اللمس قرب حواف الشاشة ومع تغير اتجاه الجهاز.

### حالات اختبار لازمة
LINE، PLINE، CIRCLE، ARC، RECTANGLE، MOVE، COPY، ROTATE، SCALE، ERASE، grip stretch، تحديد متعدد، snap، undo/redo، pinch/pan، إلغاء أمر في منتصفه.

### معيار القبول
كل كيان مرسوم يبقى بعد رفع الإصبع، ويمكن تحديده وتعديله والتراجع عنه، ولا تنتج إيماءة التكبير أو التحريك كياناً غير مقصود.

## P3 — مساحة العمل والأدوات والقوائم واللوحات

### المطلوب
1. جرد شجرة القوائم من المصدر وربط كل عنصر بمعرّف الأمر أو callback أو نافذة فعلية.
2. تصنيف الأوامر إلى أساسي ومتقدم وسياقي، وعدم وضع كل الوظائف في قائمة أفقية طويلة.
3. إنشاء شريط أدوات الهاتف حسب مجموعات: Draw، Modify، Annotate، Measure، Layers/View.
4. دعم ضغط مطول على الأداة لفتح خياراتها أو اختيار variant، مع عدم إخفاء الوصول العادي.
5. إنشاء درج أدوات قابل للبحث عن الأمر بالاسم العربي والإنجليزي والـ alias.
6. تحويل Layers وProperties وBlocks وExternal References وQuickCalc وTool Sets إلى Bottom Sheets أو Side Sheets على الهاتف.
7. على التابلت، السماح باللوحات الثابتة القابلة للطي وإعادة التحجيم.
8. الحفاظ على السياق عند فتح لوحة ثم إغلاقها؛ لا يتغير الأمر الجاري ولا يفقد التحديد.
9. نقل الخصائص الأكثر استعمالاً إلى شريط سياقي عند تحديد عنصر: اللون، الطبقة، النوع، الأبعاد، الدوران، الموقع، حسب نوع العنصر.
10. إعادة ترتيب القوائم لتناسب اللمس مع الحفاظ على كامل الوظائف المتقدمة.
11. منع القص والتداخل عند أصغر عرض مدعوم، وتوفير scrolling داخلي لكل قائمة طويلة.
12. دعم البحث في الإعدادات والأوامر.
13. جعل Undo/Redo وSave وSelection وDelete وSnap سهلة الوصول.
14. إظهار حالة الأداة النشطة بوضوح، مع زر رجوع/إلغاء للأمر.

### معيار القبول
كل وظيفة معلنة قابلة للوصول على الهاتف والتابلت، دون الاعتماد على قائمة سطح مكتب مقصوصة أو اختصارات لوحة مفاتيح فقط.

## P4 — الطبقات والخصائص وإدارة المستند

- عرض الطبقات مع تشغيل/إيقاف/قفل/تجميد وتغيير الطبقة الحالية.
- إنشاء وإعادة تسمية وحذف وإدارة خصائص الطبقات مع تحذير من القيود.
- بحث وفرز الطبقات، وتحسين قوائم الألوان والخطوط وأنواع الخطوط.
- لوحة خصائص سياقية تعرض حقول الكيان المحدد وتحررها بأنواع إدخال مناسبة.
- دعم تحديد متعدد وعرض الخصائص المشتركة.
- إدارة Blocks وAttributes وExternal References بواجهات لمس.
- إظهار تبويبات الرسومات وتبديلها وإغلاقها بأمان.
- مؤشر تعديلات غير محفوظة، وحفظ تلقائي واسترداد.
- إدارة Units وUCS وLayouts وViewports وDimension styles من صفحات مخصصة.
- مراجعة جميع اللوحات الحالية على الهاتف والتابلت، وتحديد ما يحتاج Sheet وما يحتاج صفحة كاملة.

## P5 — التصدير والطباعة والمعاينة

- شاشة Export مستقلة عن Save.
- تنسيقات متاحة فقط إذا كان لها writer فعلي على Android.
- إعدادات الورق والحجم والاتجاه والهوامش والقياس وFit وLineweights حيث يدعمها المحرك.
- معاينة قبل التصدير مع zoom/pan للورقة.
- اختيار Model/Layout/viewport الصحيح.
- اسم ملف افتراضي صحيح، MIME type، وامتداد متوافق.
- معالجة فشل plotter أو عدم توفر تنسيق برسالة عربية دقيقة.
- التحقق من جودة النصوص والخطوط والطبقات والألوان والشفافية في الناتج.
- اختبار PDF على صفحات كبيرة ورسومات كثيفة.
- لا يتم عرض DWG كخيار تصدير Android قبل إثبات writer مناسب.

## P6 — التعريب وRTL والخطوط

1. تحليل مفاتيح `ar.tsv` ومقارنتها بكل النصوص المعروضة في UI.
2. تحديد الترجمات الناقصة أو المتطابقة مع الإنجليزية أو غير الدقيقة.
3. مراجعة المصطلحات الهندسية وتوحيد القاموس العربي.
4. دعم RTL في الأشرطة والحوارات واللوحات والقوائم وسطر الأوامر.
5. الحفاظ على LTR داخل الإحداثيات والأوامر والمسارات وامتدادات الملفات والسلاسل التقنية.
6. اختبار النص المختلط: عربي + English + رقم + إشارة سالبة + فاصلة + وحدة قياس.
7. اختبار Arabic shaping وتشكيل الحروف والخطوط الاحتياطية.
8. اختبار IME العربي والإنجليزي والتبديل بينهما أثناء الأمر.
9. مراجعة اتجاه الأسهم وأيقونات التراجع/التقدم والمخططات.
10. عدم عكس الرسم الهندسي أو محور X/Y بسبب RTL.
11. إضافة وصف إمكانية الوصول لكل زر وأيقونة.
12. اعتماد اللغة العربية كلغة افتراضية مع خيار تغيير اللغة إن كان المنتج يتطلب ذلك.

## P7 — إدارة الإعدادات والتفضيلات

- حفظ إعدادات الواجهة واللوحات لكل عامل شكل (phone/tablet) دون إفساد ملف تعريف سطح المكتب.
- تفضيلات حجم الأزرار وشريط الأدوات ومكان سطر الأوامر.
- تفضيلات اللمس ومناطق الالتقاط وحساسية المقابض.
- إعدادات وحدات القياس والدقة وSnap وGrid وOrtho.
- إعدادات الحفظ التلقائي ومجلد الاسترداد.
- زر إعادة ضبط واجهة الهاتف فقط.
- ترحيل نسخ الإعدادات القديمة والتحقق من JSON التالف.
- عدم تخزين بيانات حساسة أو صلاحيات URI بطريقة غير آمنة.

## P8 — دورة حياة Android والإشعارات والأمان

- اختبار onPause/onResume وإيقاف/استئناف الرسم.
- حفظ حالة المستند المؤقتة قبل فقدان العملية.
- التعامل مع تدوير الشاشة وتغير الحجم ونافذة متعددة.
- التعامل مع استعادة GPU context وإعادة بناء موارد العرض.
- استهلاك الذاكرة عند فتح رسومات وصور كبيرة.
- عدم تنفيذ IO ثقيل على UI thread.
- إلغاء العمليات الطويلة عند إغلاق المستند أو التطبيق.
- معالجة أذونات URI الدائمة وانتهاء صلاحيات مزود الملفات.
- عدم طلب أذونات تخزين واسعة عندما يكفي SAF.
- تسجيل أخطاء قابل للتشخيص دون تسريب محتوى الرسومات.
- اختبار إعادة تشغيل التطبيق واستعادة آخر مستند/جلسة.

## P9 — الأداء وجودة الرسم

- قياس frame time وGPU upload وmesh rebuild على أجهزة منخفضة ومتوسطة وعالية.
- قياس فتح/حفظ/تصدير ملفات بأحجام مختلفة.
- مراجعة إعادة بناء mesh في الخلفية وعدم حجب الواجهة.
- اختبار zoom/pan سريع مع آلاف الكيانات.
- تخفيض استهلاك الذاكرة للصور والخطوط والـ textures.
- منع تخصيصات متكررة في حلقة الرسم.
- فحص حدود GPU والـ stencil/clip/texture على أجهزة Android متعددة.
- وضع حد آمن للملفات كبيرة الحجم ورسائل واضحة عند تجاوزه.
- قياس استهلاك البطارية والحرارة أثناء الرسم الطويل.
- مقارنة جودة الرسم بين CPU وGPU إن كان كلا المسارين مدعوماً.
- لا يتم التضحية بدقة هندسية أو جودة إخراج الملف لتحسين معدل الإطارات.

## P10 — توافق الصيغ والميزات

إنشاء مصفوفة توافق حقيقية لكل تنسيق/ميزة:
- DXF: قراءة وكتابة وإصدارات DXF المدعومة، binary/ASCII، round-trip.
- DWG: التحقق من worker/bridge والاعتماديات على Android بشكل مستقل؛ لا يُعلن قبل الاختبار.
- SVG: استيراد وتصدير، الألوان والخطوط والتحويلات.
- PNG: التصدير بالدقة والقياس، وقراءة الصور عند دعمها.
- PDF: plot/export، الورق والقياس والخطوط.
- ملفات الصور والخطوط والأنماط والسكريبتات والمراجع الخارجية.
- التمييز بين دعم المحرك النظري ودعم مضيف Android الفعلي.
- عند وجود ميزة غير متاحة: إخفاؤها أو تعطيلها مع توضيح السبب، لا ترك زر يفشل بصمت.

## 6. خطة التدقيق الوظيفي الشامل

يجب إنشاء سجل ميزات Machine-readable (CSV/Markdown أو JSON) يحتوي لكل عنصر:
- اسم الميزة بالعربية والإنجليزية.
- command ID أو اسم callback.
- الملف/الوحدة التي تنفذها.
- مدخلات الأمر ومراحله.
- هل تحتاج picker أو filesystem أو clipboard أو نافذة native أو worker؟
- حالة Android: متاح، جزئي، غير متاح، غير معروف.
- الاختبارات الموجودة والاختبارات الناقصة.
- أولوية الإصلاح والاعتماديات.
- رابط commit أو issue عند التنفيذ.

### مجموعات الجرد
1. إنشاء وفتح وإغلاق وحفظ وتبديل الرسومات.
2. الرسم ثنائي الأبعاد: خطوط، متعدد خطوط، دوائر، أقواس، مستطيلات، أشكال، منحنيات، Splines.
3. الرسم ثلاثي الأبعاد: العناصر والأوامر المدعومة فعلياً في المحرك.
4. التحديد والاختيار المتعدد والنافذة والتقاط الكائن.
5. التعديل: Move/Copy/Rotate/Scale/Mirror/Offset/Trim/Extend/Fillet/Chamfer/Stretch/Array وغيرها.
6. النصوص والخطوط والأنماط والحقول.
7. الأبعاد والقياسات والـ leaders والـ annotations.
8. الطبقات والكتل والسمات والمراجع الخارجية.
9. Hatch/Patterns/Regions/Boundaries.
10. UCS/Viewports/Layouts/Plot styles.
11. Constraints/Parametric/Groups/Blocks.
12. Query/Measure/Area/Distance/Properties.
13. Scripts/AutoLISP/aliases/macros حيث تكون مدعومة.
14. Clipboard/Import/Export/Publish/Preview.
15. إعدادات الرسم والواجهة والاختصارات.
16. كل لوحة وقائمة وحوار ونافذة من واجهة المستخدم.

لا يكفي عدّ command IDs؛ كل أمر تفاعلي يجب تتبع دورة حياته من prompt إلى commit/cancel والنتيجة وتحديث المستند.

## 7. مراحل التنفيذ وترتيبها

| المرحلة | النطاق | ناتج المرحلة | بوابة الخروج |
|---|---|---|---|
| M0 | جرد الميزات والتبعيات | سجل كل الميزات ومسارات المنصة | لا تبقى ميزة رئيسية مجهولة المسار |
| M1 | SAF وخدمات الملفات | Open/Save/Save As/Import/Export Android | round-trip وexports على جهاز |
| M2 | ثبات الرسم واللمس | آلة حالات اللمس والاختبارات | رسم/تحديد/تحرير دون فقد |
| M3 | سطر الأوامر | Mobile Command Console | IME/history/autocomplete/keywords |
| M4 | واجهة الهاتف | top bar + bottom tool dock + sheets | portrait/landscape دون قص |
| M5 | واجهة التابلت | dock workspace متكيف | panels + keyboard + stylus |
| M6 | الطبقات والخصائص والحوارات | واجهات لمس كاملة | تحرير خصائص حقيقي |
| M7 | العربية وإمكانية الوصول | RTL + قاموس موحد | اختبارات النص المختلط |
| M8 | lifecycle والأداء | استرداد وقياسات وتحسينات | لا crash/leak في السيناريوهات |
| M9 | توافق الصيغ | مصفوفة مثبتة | كل تنسيق معلن مجتاز |
| M10 | الإصدار | APK release + تقارير اختبار | كل بوابات الإصدار ناجحة |

**الترتيب الحرج:** M0 ثم M1 وM2 بالتوازي، وبعد تثبيت حدود الخدمات وحالات الإدخال يبدأ M3/M4، ثم M5/M6/M7، ثم M8/M9، وأخيراً M10.

## 8. استراتيجية الاختبار

### اختبارات الوحدة والمحرك
- لا تغيّر منطق CAD دون اختبارات هندسية regression.
- round-trip لكل صيغة معلنة.
- اختبارات حالات الأمر التفاعلي start/move/finish/cancel.
- اختبارات undo/redo وعدم تكرار commit.
- اختبارات خدمات URI باستخدام واجهات mock.

### اختبارات UI
- قياس عدم التداخل والقص في مقاسات شاشة مختلفة.
- اختبار فتح/إغلاق sheets أثناء أمر نشط.
- اختبار سطر الأوامر مع IME.
- اختبار قوائم طويلة والبحث والتحديد.
- اختبار RTL للنصوص المركبة.

### اختبارات Android Instrumentation
- فتح منتقي الملفات وإلغاءه.
- فتح URI من مزود ملفات.
- كتابة ملف وإنهاء stream.
- تدوير الشاشة وpause/resume.
- استعادة GPU.
- فقدان العملية واسترداد المستند.
- لوحة مفاتيح عربية/إنجليزية.

### مصفوفة الأجهزة
- هاتف صغير/متوسط العرض، عمودي وأفقي.
- هاتف منخفض الذاكرة.
- تابلت 8–11 بوصة على الأقل.
- Android بإصدارين مدعومين على الأقل عند تحديد الحد الأدنى النهائي.
- شاشة بكثافة مختلفة.
- جهاز يدعم قلم إن أمكن.

### اختبارات قبول يدوية
- رسم خط ثم إفلات الإصبع ثم تحديده وتحريكه.
- رسم عدة أشكال وتعديلها وحفظها وإعادة فتحها.
- فتح لوحة خصائص أثناء التحديد ثم تعديل قيمة.
- تشغيل أمر من سطر الأوامر بالكتابة والاقتراحات.
- تصدير PDF/PNG/SVG وفتح الناتج.
- تدوير الجهاز أثناء وجود تعديلات غير محفوظة.
- فتح ملف كبير واستخدام pinch/pan باستمرار.

## 9. المخاطر والقرارات التي يجب حسمها أثناء التنفيذ

| الخطر | أثره | المعالجة |
|---|---|---|
| تحويل content URI إلى Path | فشل مزودي الملفات | stream/URI abstraction |
| فقد الرسم عند فشل الحفظ | فقد بيانات | dirty state + atomic strategy + recovery |
| تضارب touch/pointer | اختفاء أو تكرار الرسم | مصدر إدخال موحد واختبارات gesture |
| لوحة المفاتيح تغطي الرسم | تجربة سيئة | window insets + console collapse |
| RTL يفسد الإحداثيات | إدخال هندسي خاطئ | عزل bidi في النصوص التقنية |
| اختلاف GPU بين الأجهزة | crash/تشوه | مصفوفة أجهزة وfallback |
| DWG worker غير متاح | ادعاء دعم مضلل | يبقى غير مدعوم حتى إثباته |
| تغيير واجهة مشتركة يكسر desktop/web | regression | cfg/platform boundaries وCI متعدد المنصات |
| حجم المشروع | صعوبة التدقيق | سجل ميزات وتغطية حسب المجموعات |

## 10. ما لا يجوز اعتباره إنجازاً

- وجود زر أو menu item ليس دليلاً على أن مساره مكتمل.
- وجود command ID ليس دليلاً على أن الأمر التفاعلي يعمل من البداية للنهاية.
- وجود codec لا يعني أن Android يستطيع الوصول إلى ملفات المستخدم.
- نجاح CI لا يعني أن APK يعمل على جهاز حقيقي.
- نجاح DXF read لا يعني أن round-trip يحافظ على كل البيانات.
- دعم DWG على desktop لا يعني دعمه على Android.
- وجود ترجمة عربية لا يعني أن كل الشاشات RTL صحيحة.
- دعم اللمس في eframe لا يعني أن كل إيماءات CAD متوافقة مع الهاتف.

## 13. حدود هذه الدراسة

هذه الوثيقة ناتجة عن فحص شجرة المستودع عند المرجع المذكور، وقراءة نقاط الدخول الأساسية لمضيف Android والواجهة وسطر الأوامر وفتح الملفات والتبادل وأوامر الملفات والتعريب، وربطها بالتصميم المطلوب. وهي خطة تنفيذ دقيقة على مستوى المنتج والمعمارية.

لا تدّعي هذه الوثيقة أن جميع ملفات المحرك البالغ عددها مئات أو جميع أوامر CAD قد اختبرت فردياً، ولا أن كل مسار filesystem أو كل صيغة قد تتبعت حتى نهايته. هذا هو عمل المرحلة M0 وسجل الميزات، ويجب أن ينتج عنه جدول حالة موثق قبل إعلان اكتمال التدقيق الوظيفي.

**المنتج لا يعتبر جاهزاً حتى تنجح بوابات الاختبار النهائية على هاتف وتابلت حقيقيين.**
